# kallistors 0.5.1

## Changes

- Faster quantification through packed index loading, exact cached matching, direct buffered
  Rust `zlib-rs` gzip decoding and borrowed EC counting after fragment sampling. Integrity checks,
  candidate order, strand filtering and every counted EC remain covered by regressions.
- Lower quantification memory through compact metadata, shared worker EC keys, bounded read
  queues, deferred names and releasing graph storage before EM. Independent EM components run
  in parallel; dominant components also share ordered EC and transcript work across the same
  pool. Scheduling follows graph workload, preserving arithmetic order and convergence; only
  bitwise fixed work is skipped.
- Faster, smaller-memory index construction through byte-proven repeat-window exclusions,
  packed bounded collections, parallel radix sorting, batched exact edge probes and compact
  graph/EC scratch. Ordered graph claims, all minimizer ties and deterministic v13 output remain.
  Stage timers are exclusive and include final cleanup in the internal total. Exact graph bounds choose direct or
  global compact location storage, reducing large graph working memory while retaining the small graph path.
- Match upstream jump/midpoint advancement over ambiguous bases, preserving mature/nascent EC
  membership and paired alignment. Two real TT-seq pairs protect both scanners and one/eight threads.
- Fix paired strand filtering, reverse-unitig backoff confirmation and abundant-node key/EC
  associations. Preserve existing v13 index loading and kallisto-style output schemas.
- Match original paired fragment sampling: a 10,000-observation goal across 8 MiB combined
  sequence buffers, with possible concurrent overshoot. All reads contribute to EC counts.
  Use `--fragment-length-samples 0` to collect all qualifying observations; single-end runs use
  the supplied fragment model. See [sampling behavior](../fragment_length_sampling.md).
- Bound HDF5 chunks to 16,384 elements with DEFLATE level 6; preserve dataset names/types/shapes.
  Native HDF5 validates every retained current transcript row. TSV formatting remains ordered.
- Use pinned fastp 1.4.0 for new read preparation, with executable/input hashes and complete
  paired-read validation for single-cell libraries.
- Extend counting to ordinary stranded, compound-barcode, tagged and paired BUS input,
  and batch BAM records for ordered parallel mapping. Preserve complete paired BUS
  fragment histograms, tag precedence, ambiguity flags and read limits.
- Borrow ordinary stranded ECs through orientation filtering and use packed positional
  graph loading. Finish bias sampling without retaining unused per-read mapping metadata.
- Share position decoding between single-end fragment and strand filters when they address
  the same annotation block, preserving both predicates. Decode native singleton coordinates
  without transient one-element vectors or intermediate serialized bitmap buffers. Pack
  native singleton groups directly into lossless position storage. Small groups fit inline on
  64-bit targets after complete coordinate and strand bounds are checked; wider and repeated
  coordinates retain full-value fallbacks. Batch independent MPHF rank-word loads during
  parallel unitig counting with bounded scratch and unchanged scalar lookup results.
  Omit unused singleton-arena flags, combine header validation with coordinate bounds,
  and share exact forward/reverse minimizer initialization for 23-base read windows.
  Encoded rescue retains exact candidate order and special-marker fallbacks.
- Speed ordinary single-cDNA BUS counting with compact index loading, packed concurrent input,
  ordered mapping/output overlap and bounded full-query reuse across workers and lanes. Retain
  full-byte collision checks, borrowed EC lifetimes, extended-mode processing and exact read limits.
- Reject disjoint-hit empty ECs in BUS records and mapping counts; retain the diagnostic
  rejection state. Cover this with a compact two-transcript regression and real single-cell preflight.
- Split graph construction, index loading, fast matching, EM/model/bootstrap work and BUS
  configuration/input into private modules with stable public entry points. Share serial/batched
  single-end filtering; preserve scanner order, arithmetic and serialized layouts.
- Consolidate diagnostics, output modules, distinct regressions and reproducible benchmark tools.
  Current manifests cover GENCODE v50 ALL and genuine TT-seq reads against only the official
  Pachter Lab mature-plus-nascent reference. Documentation covers current behavior and reproducible measurements.

## Quantification: speed and memory

Apple Silicon, eight requested threads, one warmup and three measured complete runs per case.
All reads were trimmed with fasterp 0.2.1; retrieval/trimming are excluded. The first three cases
use full GENCODE v50 ALL, and TT-seq uses Pachter Lab's published mature-plus-nascent reference.

| Library | Trimmed pairs | Current s | v0.5.0 s | Original s | Current vs original |
| --- | ---: | ---: | ---: | ---: | ---: |
| SRR13638690 · muscle | 4,410,990 | 8.119 | 17.341 | 45.158 | 5.56× |
| SRR1039508 · airway | 22,297,617 | 27.183 | 44.770 | 178.942 | 6.58× |
| SRR307903 · fibroblast | 32,878,740 | 44.249 | 85.372 | 212.451 | 4.80× |
| SRR10919051 · TT-seq | 10,261,737 | 44.307 | 91.817 | 98.344 | 2.22× |

| Library | Current GiB | v0.5.0 GiB | Original GiB | RSS reduction vs original |
| --- | ---: | ---: | ---: | ---: |
| SRR13638690 · muscle | 1.229 | 3.064 | 2.847 | 56.8% |
| SRR1039508 · airway | 1.336 | 3.801 | 3.129 | 57.3% |
| SRR307903 · fibroblast | 1.321 | 3.702 | 3.091 | 57.3% |
| SRR10919051 · TT-seq | 9.174 | 14.960 | 14.973 | 38.7% |

Every current/original complete EC map matches exactly. The published v0.5.0 binary does **not**
preserve the same complete EC map on every larger case (SRR1039508: 10 differing ECs, count L1 21;
SRR307903: 18 differing ECs, count L1 31; SRR10919051: 5 differing ECs, count L1 5). Its rows are
delivered-binary time/RSS observations, not equivalent-work speedup claims. Current/original parity
is mandatory and passes. Fixes in 0.5.1 include explicit abundant-node associations and paired
fallback/strand behavior.

Adaptive EM shares the dominant airway component across threads, removing the observed
regression against published v0.5.0. Complete fixed-EC/fixed-histogram replays preserve every
output byte, including full convergence and the final threshold update.

On the small library, current is **2.14× faster with 59.9% lower RSS**
than the published v0.5.0 download; its matched-native control gives **2.09× and
60.1% lower RSS**. At one thread current takes 38.855 s versus
93.967 s in original controls (2.42× faster).

Adaptive scheduling is selected from graph work without a user-selected mode. Retained controls, fresh
interleaved baseline checks and complete fixed-model numerical checks are documented in the
[adaptive EM comparison](../benchmarks.md#adaptive-em-scheduling).

The [benchmark guide](../benchmarks.md#eight-thread-quantification-measurement) separates startup,
read processing, model/EM and output for each library. It records full EC counts, TT-seq
mature/nascent target partitions, fragment histograms, abundance differences and individual timings.
The TT-seq library is nascent-enriched, not pure unspliced RNA. EC equality does not guarantee
identical abundances: scheduling can change sampled fragment histograms, while v0.5.0 uses all
observations. Every current/original retained output passes native HDF5 readback across all
transcript rows. The v0.5.0 download fails native large-vector readback on SRR1039508, SRR307903,
SRR10919051 (chunk-dimension encoding); its valid 17-digit TSV supplies abundance comparisons. The
small full-reference comparison independently found the same v0.5.0 HDF5 encoding limitation;
current bounded chunks pass.

## Index construction: eight threads only

Current GENCODE v50 ALL construction averages **11.449 s**, with **5.323 GiB**
peak RSS. Against retained controls, the contextual ratios are **9.71×**
versus the published v0.5.0 download and **10.81×** versus original kallisto.

The official Pachter Lab mature-plus-nascent reference builds in **96.403 s**, with
**18.397 GiB** peak RSS and **18.087 GiB** peak footprint. These current measurements
average two complete builds per reference at eight threads, with no warmup; fresh preceding-builder
controls bracket the candidates. Original's retained single control takes **903.511 s**,
a preliminary **9.37×** contextual ratio across sessions.

Large graphs use exact four-byte adaptive edge ranks, five-byte keys packed before topology,
a conservative prefix-owned rejection filter and exact sparse reference-walk landmarks.
Compact join records and earlier bitmap/MPHF retirement reduce overlapping memory.
Small graphs retain their existing layouts and pass the eight-thread construction guard.
All complete index hashes are unchanged, preserving the existing GENCODE and full TT-seq
cross-loading EC proofs. See [construction evidence](../benchmarks.md#eight-thread-index-build-measurement)
for individual measurements, stages and limits.

## Build and API notes

The evidence records the frozen adaptive-EM quantification build and latest adaptive index
builder separately. The later patch changes graph-build scratch storage; quantification kernels
retain their measured implementation.

Require Rust 1.97 or newer. Source builds use `target-cpu=native`; current CI and release
binaries use `target-cpu=generic`. The benchmark source builds use Rust 1.99.0. v0.5.0's
published workflow used native settings on its own CI runner; its CPU/compiler settings are
not assumed identical to this host. Original timing uses its official unmodified v0.52.0 binary.
The small matched-native v0.5.0 build changes only phase messages.

All current quantification runs use the normal CLI build: one warmup and three complete
measurements per configuration. The unchanged pre-adaptive 0.5.1 baseline observations are
retained, with fresh complete baseline checks interleaved after the first current measurement
in each configuration. Original kallisto and published v0.5.0 controls retain earlier verified
observations and original control rechecks. Their ratios are contextual comparisons across
sessions. All reported measurements and control checks are retained.
Individual timings, power, CPU activity, swap and interruption flags are retained in the
[measurement evidence](../benchmark-results.json). These workload-specific ratios do not predict
every assay or the performance of generic prebuilt binaries.

`strength_reduce 0.2.4` supplies exact precomputed MPHF divisors. Rust callers with exhaustive
`PseudoalignOptions` literals must include `fragment_length_samples`; using
`..PseudoalignOptions::default()` selects the sampling goal. Existing public entry points remain.
See [compatibility limits](../compatibility.md) and the [development guide](../development.md).
