# kallistors 0.5.1

Paired and single-end RNA-seq quantification with compact index/EM storage, parallel processing
and kallisto-compatible output. Existing v13 indexes remain usable.

## Matching and storage

- Abundant-node matching associates explicit stored k-mer keys with EC records, so Bifrost
  hash-table order does not determine transcript assignments.
- Singleton minimizer buckets, sequence/EC metadata, loader scratch and EM arrays use compact
  storage. Wide values retain explicit fallbacks.
- Matching uses exact grouped hashing, precomputed MPHF divisors, compact caches and packed
  reference windows. AArch64 NEON encoding has a portable fallback; candidate and tie order
  are preserved.
- Parallel EM updates retain each transcript's arithmetic order. Paired input queues are bounded,
  and blocked producers are released after input errors.

## Fragment sampling

Paired estimation follows original kallisto's 10,000-observation goal and 8 MiB combined-sequence
buffers. Quotas carry across parser chunks; concurrent workers can overshoot the goal. All reads
contribute to EC counts. Use `--fragment-length-samples 0` to collect all qualifying observations:

```bash
kallistors quant -t 8 -i transcripts.idx -o quant_out \
  --fragment-length-samples 0 reads_1.fastq.gz reads_2.fastq.gz
```

Sampling can affect effective lengths, EM stopping and ambiguous isoform estimates. See
[sampling behavior](../fragment_length_sampling.md) and [compatibility](../compatibility.md).
Single-end quantification uses the supplied `-l` / `-s` model.

## Output and API

Quantification overlaps TSV and HDF5 output when threaded. HDF5 uses DEFLATE level 6 and chunks
bounded to 16,384 elements, with kallisto-style dataset names, types and shapes. Plaintext
bootstrap output is available with `--plaintext`; bootstrap RNG values can differ from upstream.

Diagnostics, quantification writers and BUS genome/BAM output have dedicated modules.
Existing public entry points remain available. Exhaustive `PseudoalignOptions` literals must
include `fragment_length_samples`; `..PseudoalignOptions::default()` selects the sampling goal.

## Builds and validation

Rust 1.97 or newer is required. Source builds use `target-cpu=native`; CI and release binaries
use `target-cpu=generic`. `strength_reduce 0.2.4` provides exact precomputed MPHF divisors.

The [development guide](../development.md) describes required checks and source organization.
The [benchmark guide](../benchmarks.md) documents public data retrieval, trimming, GENCODE cDNA
and Pachter Lab mature-plus-nascent references, phase timing, memory measurements and full EC
comparisons with original kallisto. One quantification runner handles direct inputs and configured suites,
requires complete EC parity before timing, and shares execution/memory code with index benchmarks.
Reports include native HDF5 checks, fragment statistics and numeric abundance comparisons.
Performance is workload- and hardware-dependent.
