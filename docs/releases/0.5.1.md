# kallistors 0.5.1

Paired and single-end RNA-seq quantification with compact index/EM storage, parallel processing
and kallisto-compatible output. Existing v13 indexes remain usable.

## Matching and storage

- Abundant-node matching associates explicit stored k-mer keys with EC records, so Bifrost
  hash-table order does not determine transcript assignments.
- Singleton minimizer buckets, sequence/EC metadata, loader scratch and EM arrays use compact
  storage. Wide values retain explicit fallbacks.
- Matching uses exact grouped hashing, precomputed MPHF divisors, compact caches and packed
  reference windows. AArch64 NEON encoding has a portable fallback; candidate and tie order
  are preserved.
- Parallel EM updates retain each transcript's arithmetic order. Paired input queues are bounded,
  and blocked producers are released after input errors.
- Index construction excludes only byte-proven repeat windows, retains seam windows and complete
  metadata, and deduplicates bounded groups before parallel radix sorting. Shared-end and sparse
  internal anchors select candidates; full byte equality proves each excluded interval.
- Canonical-edge symmetry reduces duplicate probes. Exact singleton/small-bucket descriptors,
  active query batches and AArch64 key/positive-target cache hints reduce lookup stalls. Idempotent atomic updates
  preserve both endpoints; the first-edge fast path and larger-rank fallbacks remain exact.
- One requested worker pool handles nested stages. Edge finalization and branch
  sequence materialization run in parallel; serial ordered claims preserve graph order. Narrow
  path steps, compact oriented starts/join links, moved sequence buffers and stable flat
  transcript-location scratch reduce temporary work. Residual preparation stays bounded with
  serial fallback for long components.
- Completed parallel collection groups are losslessly packed before their words are sorted. Collection
  buffers are reused, packed records retain transcript order, and identifier bytes share an arena
  until mapping finishes. Original strings, lengths and normalization behavior are preserved.
- Exact prefix ranks, k-mer locations and join states use compact representations with complete
  fallback handling. Whole-unitig transcript runs omit repeated bounds; EC positions use
  contiguous grouped storage. Counted parallel filling avoids overlapping start shards and output.
- MPHF keys retain their exact serialized order while fitting survivor/bucket arrays use 32-bit
  entries. Stable atomic rank fields replace the separate continuation-degree snapshot.
  Completed scratch pages are reclaimed before later allocations overlap them on macOS/Linux.
- FASTA normalization runs in parallel while ambiguity replacement retains its RNG and input
  order. Buffered line parsing, original lengths, polyA handling and UTF-8 errors are preserved.
- Exact unitig continuations accelerate transcript runs. EC construction, minimizers, per-worker
  MPHF collision marking and grouped node serialization retain deterministic output. All minimizer
  ties remain; direct sequence packing/checksums have portable fallbacks. MPHF timing is separate
  from writing, and the internal total includes final allocation cleanup.
- Paired strand flags retain the required annotations; filtering away all transcripts rejects
  the match. CLI regressions cover FR/RF transcript selection at one and eight threads.
- Validated backoff probes can confirm jumps on either unitig orientation. A full-index SVIL
  regression checks complete ECs with the Rust-built reference in both scanners.

## Index construction measurements

On Apple Silicon at eight threads, the complete GENCODE v50 ALL reference (670,670 transcripts)
built in a median **12.39 s**, with **5.08 GiB peak RSS** and **4.59 GiB peak footprint**. One warmup preceded three measured
builds from the same uncompressed FASTA. CPU activity was sampled throughout; this is a
workload-specific measurement. The [benchmark guide](../benchmarks.md) describes preparation,
measurement scope and compatibility checks.

## Fragment sampling

Paired estimation follows original kallisto's 10,000-observation goal and 8 MiB combined-sequence
buffers. Quotas carry across parser chunks; concurrent workers can overshoot the goal. All reads
contribute to EC counts. Use `--fragment-length-samples 0` to collect all qualifying observations:

```bash
kallistors quant -t 8 -i transcripts.idx -o quant_out \
  --fragment-length-samples 0 reads_1.fastq.gz reads_2.fastq.gz
```

Sampling can affect effective lengths, EM stopping and ambiguous isoform estimates. See
[sampling behavior](../fragment_length_sampling.md) and [compatibility](../compatibility.md).
Single-end quantification uses the supplied `-l` / `-s` model.

## Output and API

Quantification overlaps TSV and HDF5 output when threaded. HDF5 uses DEFLATE level 6 and chunks
bounded to 16,384 elements, with kallisto-style dataset names, types and shapes. Plaintext
bootstrap output is available with `--plaintext`; bootstrap RNG values can differ from upstream.

Diagnostics, quantification writers and BUS genome/BAM output have dedicated modules.
Existing public entry points remain available. Exhaustive `PseudoalignOptions` literals must
include `fragment_length_samples`; `..PseudoalignOptions::default()` selects the sampling goal.

## Builds and validation

Rust 1.97 or newer is required. Source builds use `target-cpu=native`; CI and release binaries
use `target-cpu=generic`. `strength_reduce 0.2.4` provides exact precomputed MPHF divisors.

The [development guide](../development.md) describes required checks and source organization.
The [benchmark guide](../benchmarks.md) documents public data retrieval, trimming, GENCODE cDNA
and Pachter Lab mature-plus-nascent references, phase timing, memory measurements and full EC
comparisons with original kallisto. One quantification runner handles direct inputs and configured suites,
requires complete EC parity before timing, and shares execution/memory code with index benchmarks.
Reports include native HDF5 checks, fragment statistics and numeric abundance comparisons.
Performance is workload- and hardware-dependent.
