# kallistors 0.6.1

This patch release fixes recovery after failed matching jumps in the general and fast scanners.

## Changes

- Match original kallisto 0.52.0 by restricting recovery to the next valid k-mer probe,
  then resuming ordinary lookup. Keeping recovery active through the proposed jump endpoint
  could hide a later conflicting hit and incorrectly retain a mapping.
- Keep the recovery probe pending across invalid bases until a valid k-mer is available.
- Add the real TT-seq pair `SRR10919051.4665298` as a regression. Both scanner traces and
  paired mapping at one and eight threads must reject its conflicting transcript hits.
  The [development guide](../development.md#test-strategy-and-prerequisites) describes the
  reference prerequisite and command for these opt-in tests.

## Compatibility

Existing CLI and Rust APIs, kallisto v13 indexes and output schemas remain compatible.
Existing indexes can be reused. See the [compatibility guide](../compatibility.md).

## Benchmarks and previous changes

The existing 0.6.0 benchmark reports remain relevant and retain their recorded protocols
and tool versions. See the [benchmark guide](../benchmarks.md#latest-completed-results)
for the published comparisons and the [0.6.0 release notes](0.6.0.md) for the preceding changes.
