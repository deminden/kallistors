# kallistors 0.5.0

A major performance release for full transcriptome quantification: faster index loading, exact
encoded matching, and parallel EM with preserved contribution order. Complete EC count maps remain
exact against original kallisto in all six documented paired/single-end cases.

## Measured speed increases

Apple Silicon macOS, **eight threads**, **4,411,003 fastp-trimmed SRR13638690 read pairs**, and the
same upstream-built **GENCODE v50 ALL-transcript index with 670,670 targets**. Timings include
index loading, all reads, EM, default HDF5/TSV output and process shutdown.

| Tool | Full elapsed time | Peak RSS |
| --- | ---: | ---: |
| Original kallisto v0.52.0 | 47.673 s | 2.85 GiB |
| kallistors 0.5.0 | 17.532 s | 3.01 GiB |

**2.72x faster; 63.22% less elapsed time; 5.7% more peak resident memory.** This is one
measured pair with already warmed inputs, not a repeated median. Both processes were measured
using macOS `/usr/bin/time -l`, with optional Rust stage timings omitted. No compiler or
correctness job ran concurrently. The before-run CPU snapshot recorded WindowServer at 45.0%
before original kallisto and no other process above 25% before kallistors. Results are specific to
this workload and host; they do not establish a single-end or index-build speed claim.

The [performance report](https://github.com/deminden/kallistors/blob/v0.5.0/docs/performance_0.5.0.md)
gives exact byte counts, the memory allocation diagnosis, reproduction commands and complete EC
validation. Historical measurements remain dated in the benchmark documentation.

## Memory changes

Reconstruct bitmap-selected loader minimizers directly from packed bases, eliminating full
per-position minimizer tables. Ordinary counting uses one flat EC table, including jump bounds;
positional filters, strand handling, diagnostics and alternate scanners retain the nested metadata
they need. Reuse minimizer count buffers for prefix offsets and release loading scratch after
its last use. These changes preserve packed matching and parallel index/EM work.

Peak RSS covers the complete process lifetime and all threads sharing its address space. GiB means
2^30 bytes. The measured difference against original kallisto is **0.16 GiB** (1.057x). Positional
and diagnostic modes retain additional metadata and can have different memory requirements.

## Main changes

- **Remove the reference-wide scan from every read.** Calculate the on-list cardinality only when
  constructing a synthetic D-list hit. Ordinary reads avoid scanning all 670,670 transcript flags.
- **Pack unitig bases into u64 words.** Extract candidate k-mers with shifts and one/two word loads.
  Reuse validated read words for canonical minimizer representation and adjacent read encoding.
  Roll the exact REP hash states within each k-mer; preserve strict bounds, ties and search order.
- **Load indexes faster.** Preserve buffered bytes when skipping stored node k-mers. Resolve unitig
  MPHF lookups in parallel and append events in their original order, preserving bucket order.
  Derive minimizers from packed bases and use a compact counting index with unchanged jump bounds.
- **Parallelize EM without changing per-transcript sums.** Reset and check active transcripts only.
  Compute denominators independently, then sum transposed incoming edges per transcript in original
  EC/edge order. Preserve initialization, zero iterations, convergence and bias-weight refresh.
- **Reuse matching work safely.** Cache positive primary matches and retain MPHF scratch per worker.
  Cached primary misses still populate the fallback candidates. Unique index/k/g ownership prevents
  stale reuse across indexes; oversized minimizer tie lists are recomputed in full.
- **Reduce input/counting overhead.** Skip discarded FASTQ lines without copying their bytes; use
  fast numeric EC hashing while still comparing complete vectors for equality.
- **Make comparisons reproducible.** `scripts/benchmark_quant_variants.py` alternates complete runs,
  retains commands/CPU snapshots/medians and final outputs, measures peak RSS with `--memory`,
  and supports original kallisto with
  `--no-timings`. Existing data retrieval, fastp trimming and paired/single-end workflows remain.

## Compatibility and correctness

No index-format, command-line syntax or output-layout migration is required. Default HDF5 output
remains enabled. The paired empirical fragment model, single-end Gaussian model and bootstrap
sampling behavior are unchanged from 0.4.2. Rust 1.97 remains the declared minimum; validation
uses Rust 1.99.0 and the same locked dependency graph as 0.4.2.

`quant -t N` now also uses N threads for EM, in a phase after mapping. The default thread count
remains one. Existing library entry points stay serial; callers can opt into parallel EM using
`em_quantify_with_fragment_histogram_threaded(..., options, threads)`. Existing code does not need
an API migration. Users who explicitly select multiple CLI threads should account for the higher
EM CPU utilization.

| Dataset | Exact paired nonzero ECs | Exact single-end nonzero ECs |
| --- | ---: | ---: |
| ERR2260014 | 3,604 | 3,534 |
| DRR023395 | 181,044 | 146,676 |
| SRR13638690 | 190,711 | 192,645 |

All six complete count maps match diagnostic upstream output: zero differing classes and zero
absolute count difference. Serial/threaded numerical regressions compare
results exactly with sparse targets, zero iterations, Gaussian/empirical fragment models and bias
refresh. Encoding, cache lifetime, loader order, CRLF/truncated FASTQ and concatenated gzip members
have dedicated regression coverage. Compact/full loaders additionally agree on bucket order,
EC values, bounds and complete read hits in both scanners; positional loading retains annotations. The full-index TTN/AGAP12P regression checks both scanners.

Exact EC parity does not imply byte-identical abundance against upstream. Kallistors retains all
qualifying paired fragment observations while upstream samples near a bounded goal; the small
paired abundance differences documented in 0.4.2 remain. Bootstrap RNG differences and the lack of
bias-enabled real-data upstream validation also remain documented limitations.
