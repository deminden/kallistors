# kallistors 0.4.2

This release corrects paired-end effective lengths and a reproducible single-end scanner mismatch,
refreshes dependencies, and adds documented real-read comparison workflows. No command-line
option or index format migration is required. Rust 1.97 remains the declared minimum; local
validation used Rust 1.99.0 on Apple Silicon macOS.

## Quantification corrections

**Paired fragment model.** Quantification previously fitted a Gaussian to the observed fragment
mean and SD. It now uses the empirical histogram: for transcript length L, the conditional mean
includes observations with fragment length at most L. The resulting effective lengths feed EM,
bias correction, and bootstrap quantification. Single-end input retains its supplied Gaussian
model. Existing paired data should be quantified again when comparable transcript abundance is
required, particularly for short transcripts.

**Fallback probe.** Both fast and general scanners now finish the next valid k-mer's fallback
probe without initiating another jump. Two identical 126-base SRR13638690 reads previously
assigned to eight TTN isoforms now map uniquely to TTN-206, matching upstream kallisto v0.52.0.
The fix follows the executed upstream loop; suppressing jumps over the entire fallback interval
was rejected because it lost other alignments.

The existing `em_quantify` library entry point remains available with its Gaussian model.
Library callers with paired observations should use the new
`em_quantify_with_fragment_histogram` entry point, passing `EcCounts.fragment_length_hist`.
The updated README contains an example. An explicitly empty or all-zero empirical histogram
is rejected; omitting the histogram retains the Gaussian path.

## Compatibility evidence and remaining differences

Complete nonzero EC count maps match upstream in all six cases: paired and single-end modes for
ERR2260014, DRR023395, and SRR13638690. All checks use the same upstream-built GENCODE v50
ALL-transcript index with 670,670 targets and fastp-trimmed reads.

| Paired dataset | TPM mass difference before | After |
| --- | ---: | ---: |
| ERR2260014 | 4.46% | Floating-point noise |
| DRR023395 | 1.05% | 0.010% |
| SRR13638690 | 3.94% | 0.080% |

TPM mass difference is half the sum of absolute transcript TPM differences divided by upstream's
total TPM. These are compatibility comparisons, not biological accuracy measurements. Upstream
samples fragment observations and can overshoot its goal with multiple workers; kallistors keeps
all qualifying observations. The remaining paired differences reflect those histograms, with
additional text rounding in the official release comparison. Bootstrap random sampling still
differs from upstream, and bias-enabled real-data parity was not established by this audit.

Small and medium single-end abundances agree within floating-point precision. The large
single-end EC map, warmup counters, and isolated TTN regression match upstream; post-fix full
abundance comparison and a new single-end timing median were not completed; the timed benchmark
was stopped after warmups.

unnecessary for building kallistors.

## Reproducible comparisons

- `environment.yml` supplies optional R 4.6.1 and fastp 1.4.0; neither is a Rust build dependency.
- `scripts/prepare_local_benchmark.sh` retrieves three ENA paired runs and the full GENCODE v50
  transcript FASTA, checks ENA MD5s and gzip integrity, and trims adapters/low-quality ends.
- `scripts/benchmark_local_index.py` compares index builds with one warmup and three measured runs.
- `scripts/benchmark_local_reads.py` compares paired and mate-1 single-end runs, selectable samples
  and thread counts, with one warmup and median-of-three timing. It alternates tool order, can
  retain final abundance outputs, and saves completed run records outside the timed region.
- `scripts/compare_abundance.py --summary-json` reports effective lengths, missing targets,
  errors among expressed transcripts, common-precision discrepancies, and TPM mass difference.
- `scripts/diagnostics/kallisto_v0.52.0_quant_audit.patch` preserves the upstream diagnostic build
  used for full EC/histogram inspection and high-precision abundance output.

Raw FASTQs, indexes, and generated outputs stay outside Git. Small regression read fixtures and
the retrieval/comparison procedures are tracked. Sources, checksums, trimming parameters, and
commands are in the [local comparison guide](https://github.com/deminden/kallistors/blob/v0.4.2/docs/local_read_comparison_2026-10-14.md).

## Performance

The completed post-fix large paired comparison at eight threads has medians of **46.694 seconds
for kallisto and 78.123 seconds for kallistors**, from one warmup and three measured runs per tool.
Those elapsed times were recovered from console output to 0.001-second precision after the
remaining single-end repetitions were stopped. This release addresses correctness; it does not
establish an overall speed advantage. The earlier GENCODE v50 index build was 1.13x faster, and
some earlier single-end workloads favored kallistors, but those timings precede these two fixes.

See the [fix report](https://github.com/deminden/kallistors/blob/v0.4.2/docs/quantification_fixes_2026-10-14.md) for all EC counts, abundance results,
regression commands, and timing provenance; the [audit](https://github.com/deminden/kallistors/blob/v0.4.2/docs/quantification_mismatch_audit_2026-10-14.md)
contains the original mismatch evidence.

## Publication

The version is set to 0.4.2. Local implementation checks passed before the version bump:
workspace tests, strict Clippy, and the explicitly enabled GENCODE v50 regression for both
scanners. Full-read EC maps were additionally checked against diagnostic upstream output.
The 0.4.2 release build reports the correct version, and the locked crates.io dry run successfully
packages and compiles the crate, including the license and regression fixtures.

The [release workflow](https://github.com/deminden/kallistors/blob/v0.4.2/docs/development.md#release-workflow) describes the final checks, crate dry
run, tag, and publication steps. Pushing `v0.4.2` triggers crates.io publication and four-platform
binary builds. Binary archives include the README, license, changelog, and documentation, with
SHA-256 checksums. CI and publication checks use the locked dependency graph. The binary workflow
uses these notes when creating the GitHub Release. Developer and benchmark commands are run from
a source checkout; bundled documentation is also included for reference.
